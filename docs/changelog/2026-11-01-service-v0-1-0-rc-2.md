# 2026-11-01 — service-v0.1.0-rc.2: the write service joins the release

**Service line, second pre-release** · package unchanged (`11.3.0`) ·
[ADR-0003](../adr/0003-gradle-build-and-service-release-line.md) ·
[ADR-0004](../adr/0004-dual-artifact-line.md) ·
[#174](https://github.com/spec-kitty/spec-kitty-events/issues/174)

`service-v0.1.0-rc.1` was cut before PR #173 merged, so it carries only the read service.
`service-v0.1.0-rc.2` adds `command-cli`, the events write service (#156). Core needs it to
pin the write service (spec-kitty/spec-kitty#6195 and gap 6 of
spec-kitty/spec-kitty#6915). The tag goes on a commit of `main`. `service-release.yml` then
builds, checks, attests and publishes the release as a GitHub pre-release, never marked
latest. Nothing reaches PyPI: the package line (`v*`) is separate and stays at `11.3.0`, the
version this release is built and tested against.

## What the release publishes

`<ver>` is `0.1.0-rc.2`. The asset set is the
[ADR-0003 asset table](../adr/0003-gradle-build-and-service-release-line.md#release-assets),
exactly. `scripts/release/service-release-assets.sh` refuses a set with anything missing
or extra.

That makes 13 assets, 13 `.sha256` files and `SHA256SUMS`: 27 files. Each of the 13 assets
has a build-provenance attestation.

### Native or jar, per platform

The same for both services:

| Platform | What runs |
|---|---|
| Linux x86-64 | native |
| Linux ARM64 | native |
| macOS on Apple silicon | native |
| Windows x86-64 | native (`.exe`) |
| macOS on Intel, Windows ARM64, any other platform | no native build: the jar, on Java 25 or newer |

The binaries are unsigned, so macOS Gatekeeper and Windows SmartScreen warn on first run, as
with rc.1.

### What the write service does in this release

`command-cli` implements the process contract
([`contracts/mission-write/LAUNCHER.md`](https://github.com/spec-kitty/spec-kitty-events/blob/main/contracts/mission-write/LAUNCHER.md)):
start, single instance, ready, stop, the handshake, the health check, the request guard and
idle exit. **Every write still refuses fail-closed** with
`500 STATUS_EVENT_PERSISTENCE_VERIFICATION_FAILED` and writes nothing. The write core follows
in #160 (the canonical writer) and #161 (the lane authority), in a later release. This release
lets core pin and launch the write service now.

## How to verify a download

```bash
sha256sum --check --ignore-missing SHA256SUMS
gh attestation verify <asset> --repo spec-kitty/spec-kitty-events \
  --signer-workflow spec-kitty/spec-kitty-events/.github/workflows/service-release.yml \
  --source-ref refs/tags/service-v0.1.0-rc.2
```

Core pins the write service with
`spec-kitty service vendor --service write-service --tag service-v0.1.0-rc.2`. The command
works as it does for the read service: it resolves the tag to its commit, downloads
`SHA256SUMS`, maps the `command-cli` assets onto the pin by name and checks each download.
[Service protocol and releases](../guides/service-protocol-and-releases.md#cut-a-release)
describes the release steps.
