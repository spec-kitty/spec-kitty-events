section: Changed
---

- The packaged `spec_kitty_events.conformance` `status_transition_parity` corpus gains an
  optional `implementationEvidencePresent` key (boolean or null) on a request unit, in
  `case.schema.json`, `status_transition_parity/README.md` and `conformance/README.md`. It is
  core's request-only `implementation_evidence_present`: it is never part of a unit's rows.
  `scripts/conformance/generate_transition_parity.py` passes it to core's `emit_status_transition`
  and names it on the wire unit only when a case sets it. Five oracle-backed cases are added,
  generated by running core at the pinned SHA: `guard-evidence-explicit-false` (refused with
  `implementation_evidence_required`), `guard-evidence-explicit-true`,
  `guard-evidence-explicit-true-subtasks-incomplete` (refused for subtasks, so the field never
  affects that half), `guard-evidence-explicit-false-forced` and
  `guard-evidence-explicit-false-other-transition` (both accepted). `unreachable.json` drops its
  `partial` entry for `implementation_evidence_required`, because both halves are now reached, and
  restates why no wire request can produce `workspace_context_required`. Consumers that validate
  units against their own copy of the schema must allow the new key (#236; #224).
