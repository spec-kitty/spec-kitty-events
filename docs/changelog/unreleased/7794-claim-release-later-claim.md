- `spec_kitty_events.diary.reduce_parsed` no longer lets a `release_runtime_claim` annotation erase the claim a later re-claim set (spec-kitty/spec-kitty#7794). Annotations fold in a pass after every transition, so a release stamped before a `planned -> claimed` cleared that claim's `agent`, `shell_pid` and `shell_pid_created_at` as if it had come after it: claim, release, re-claim by another agent reduced to `agent=None`, `shell_pid=None`. A release now restores each claim slot that a real transition ordered after it by `(at, event_id)` wrote, and clears only the rest; that later claim then owns the whole triple, so an `agent` or `shell_pid` replanted in the same releasing delta never mixes with it. On an equal `at`, only a string transition `event_id` can order after the release. A reconstruction seed's restatement does not count as a later claim. A release after the claim, or with no later claim, clears as before, and every other annotation slot still folds latest-wins after the transitions. The write service's core-parity fold (`command-cli`, `AnnotationFold`) makes the same change; the read service does not port the annotation pass and is unchanged.
