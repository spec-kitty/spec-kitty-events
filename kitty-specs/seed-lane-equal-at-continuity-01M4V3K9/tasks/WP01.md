# WP01 — Equal-`at` `approved -> done` settles its approval (spec-kitty-events#87)

## Goal

A rollback-shaped `migration:` reconstruction seed must not reopen a `done` work
package when the real `approved -> done` shares its approval's `at` and sorts before it
by `event_id`. Make the reducer treat that `done` as settling its approval regardless of
`event_id` order.

## Context

- File: `src/spec_kitty_events/diary.py`. The seam is `_is_bare_sibling` — its
  "nothing real was built upon the approval" look-ahead uses
  `(ev.at, ev.event_id) > key` over non-seed events leaving `APPROVED`. When the
  `approved -> done` shares the approval's `at` and has a smaller `event_id`, it is not
  `> key`, so it is not counted as building upon the approval, and arm-(ii) continuity
  independently drops the earlier-sorting `done`.
- Reproduction (reduces to `("in_progress", "changes_requested")` on current main;
  must become `("done", "approved")`):
  `_SEED_PRE`; `in_review -> approved` at `10:04:00` id `_ulid(6)`;
  `approved -> done` at `10:04:00` id `_ulid(5)`; rollback seed at `11:00:00`.

## Subtasks

- **T001 (red-first)**: regression test (`@pytest.mark.regression`, issue 87) in
  `tests/test_status_diary_reducer.py` asserting the reproduction resolves to
  `("done", "approved")`. Confirm it is RED before T002 (swap in `main`'s `diary.py`
  or run before the fix); record the failing output as evidence (not committed).
- **T002 (fix)**: make the built-upon determination order-independent for an equal-`at`

  `_is_bare_sibling` look-ahead; keep the normal ordering and the genuinely-bare

- **T003 (verify)**: T001 green; full `tests/test_status_diary_reducer.py` + packaged
